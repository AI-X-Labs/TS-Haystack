# Sleep PSG Windowed-Natural Retrieval Benchmark

A retrieval benchmark for polysomnography (PSG) data built from **real recordings sliced into context windows** — no synthetic needle insertion. Uses the PhysioNet 2018 Challenge dataset (994 subjects, 13-channel PSG at 200Hz, ~7h recordings).

## Design Rationale

Real sleep follows structured cycles (Wake → N1 → N2 → N3 → REM → repeat, ~90min per cycle). Unlike HAR accelerometer data where activities can occur at any time, sleep stages have strict temporal ordering. Inserting synthetic segments (e.g., random REM into sustained N3) creates unrealistic signals.

Instead, we **slice unmodified recordings into context windows** of varying length and generate questions from whatever natural annotations fall inside the window. The signal is real sleep from a single subject; the only knob is the window length, which varies the difficulty (longer = more events to reason about).

A per-(subject, context-length) **window index** is built once: it enumerates valid window starts (those containing at least one regime bout) by sliding a stride across each recording. Questions are then generated by drawing random `(subject, window_start)` pairs from the index, clipping the timelines to the window, and asking the standard tasks against the windowed timeline.

## Participant Splitting

Subjects are split deterministically (seed=42) into train/val/test at the participant level:
- **Train**: 695 subjects (70%)
- **Val**: 149 subjects (15%)
- **Test**: 150 subjects (15%)

The split is shared across all tasks and both datasets. A subject used for training in one task is never used for testing in another.

## Task Descriptions

All bout-indexed tasks use **ordinal references** scoped to the window (e.g., "the 2nd N3 bout" means the 2nd N3 bout *inside this window*, not the 2nd N3 of the night). When a bout straddles a window boundary it is clipped to the window edge before being indexed.

### Sleep Stages Dataset (8 tasks)

| Task | Question Example | Answer Type |
|---|---|---|
| **Existence** | "Is there any N3 in this recording?" | boolean |
| **Localization** | "When did the 2nd N3 bout occur?" | time_range |
| **Counting** | "How many REM bouts are there?" | integer |
| **Ordering** | "Did the 3rd N3 occur before the 2nd REM?" | boolean |
| **State Query** | "What sleep stage during the 5th rera?" | category |
| **Antecedent** | "What stage came before the 3rd N3?" | category |
| **Comparison** | "Which was the longest N2 bout?" | time_range |
| **Multi-Hop** | "When did the 2nd N1 after the 3rd REM?" | time_range |

### Arousals Dataset (7 tasks)

| Task | Question Example | Answer Type |
|---|---|---|
| **Existence** | "Is there any mixed_apnea in this window?" | boolean |
| **Localization** | "When did the 8th hypopnea occur?" | time_range |
| **Counting** | "How many central_apneas are there?" | integer |
| **Ordering** | "Did the 3rd rera occur before the 5th hypopnea?" | boolean |
| **Antecedent** | "What arousal occurred before the 8th obstructive_apnea?" | category |

**Why existence is gated**: at the omitted lengths, the regime saturates and labels degenerate to "yes". For `sleep_stages` at `full`, >90% of subjects show all 5 stages. For `arousals` at `1h` / `full`, rera and hypopnea are present in ~96% of subjects.

Counting at short windows naturally produces zero answers (e.g. ~30% of 1h windows have no N3) — this is the main reason existence and zero-counting are useful at the new scales but were dropped from the original full-recording benchmark.

### Task Details

All tasks operate on a **window-scoped recording**: timelines are clipped to the window and shifted so the window begins at time 0. Ordinals therefore count bouts *within the window*.

**Existence**: Decide answer first (50/50 coin flip), then pick a target from `present` or `absent` regime activities for the window. Naturally balanced at short context lengths because many regime activities are missing from any given window; gated off at lengths where the regime saturates.

**Localization**: Pick activity with ≥1 bout in window, pick random ordinal, answer is the bout's time range (window-relative).

**Counting**: Pick any regime activity (including absent ones for answer=0). At 15min/1h windows, zero counts are common — a natural source of label diversity that the full-recording benchmark lacked.

**Ordering**: Balance-first — decides answer (true/false) first via coin flip, then finds ordinal pairs that produce the desired temporal order. Guarantees 50/50 label balance.

**State Query** (sleep_stages only): Cross-timeline task — picks an arousal event by ordinal from the (window-clipped) arousals timeline, then looks up the sleep stage at the arousal's midpoint from the (window-clipped) sleep stages timeline.

**Antecedent**: For sleep stages, asks "what stage came before the Nth bout?" (answer is a sleep stage). For arousals, asks "what arousal occurred before the Nth arousal?" (answer is another arousal type). Uses the window's sorted timeline to find the immediately preceding bout.

**Comparison**: Pick activity with ≥2 bouts and distinct durations in the window. Randomly asks for "longest" or "shortest". Verifies uniqueness (no ties).

**Multi-Hop**: Pick anchor (activity + ordinal) and target activity, both in the window. Pick direction (before/after). Count target bouts in that direction, pick Kth. Tests multi-step reasoning: find anchor → scan direction → count K occurrences.

## Why Anomaly Tasks Are Not Included

- **Anomaly Detection** (arousals): equivalent to Existence on the arousal regime. Already covered by the existence task at 100s/15min, where many windows naturally contain zero arousals.
- **Anomaly Localization**: with median 150 arousals/subject, "find *the* anomaly" is ambiguous. Subsumed by the localization task.

(**Existence** was previously dropped because full recordings made it trivially "yes". With the windowed-natural approach it is restored at the context lengths where labels are naturally balanced — see gating above.)

## Parquet Output Format

Generated parquet files are **lightweight metadata** — no signal data embedded:

| Column | Type | Description |
|---|---|---|
| subject_id | string | Subject identifier for signal loading |
| recording_duration_ms | int64 | Window length in milliseconds (== context length, or full duration) |
| label_class | string | "sleep_stages" or "arousals" |
| task_type | string | Task name |
| context_length_s | float64 | Context length in seconds, or `-1.0` for `full` |
| window_start_ms | int64 | Absolute window start in the recording |
| window_end_ms | int64 | Absolute window end (exclusive) |
| question | string | Natural language question |
| answer | string | Ground truth answer |
| answer_type | string | boolean, integer, category, time_range |
| metadata | string (JSON) | Task-specific metadata (timestamps are window-relative) |
| is_valid | bool | Validation flag |
| validation_notes | string | Validation notes (if invalid) |

Signals are loaded on-the-fly from `.npy` memmap files at evaluation time by slicing `[window_start_ms : window_end_ms]` of the subject's recording. **All timestamps inside `metadata` and inside `answer` strings are relative to the window start** (i.e. the window is presented to the model as starting at `00:00:00`).

## Usage

### Step 0: Download raw PSG data (~268 GB)

The raw data comes from the PhysioNet 2018 Challenge. We host pre-converted `.npy` files on Hugging Face for convenience. **The full dataset is ~268 GB** (994 subjects, ~270 MB each).

**Option A: From Hugging Face (recommended — pre-converted .npy files)**

```bash
# Requires: pip install huggingface_hub
huggingface-cli download nz00shuuuu/sleep_psg_raw_npy --repo-type dataset --local-dir data/sleep_psg/training
```

Each subject directory contains:
- `{subject_id}.npy` — 13-channel PSG signal, float32, shape `(N_samples, 13)` (~250-300 MB)
- `{subject_id}.hea` — WFDB header (channel names, sampling rate, sample count)
- `{subject_id}.arousal` — WFDB annotation file (sleep stages + arousal events)
- `{subject_id}-arousal.mat` — Arousal vector (alternative annotation format)

Place downloaded files in `data/sleep_psg/training/{subject_id}/`.

**Option B: From PhysioNet S3 (requires .mat → .npy conversion)**

```bash
# Download from PhysioNet S3 (~135 GB .mat files, no credentials needed)
.venv/bin/python3 src/datasets/sleep_psg_haystack/scripts/download_sleep_psg.py --all

# Convert .mat → .npy for memory-mapped loading (one-time, doubles disk usage temporarily)
.venv/bin/python3 src/datasets/sleep_psg_haystack/scripts/convert_sleep_psg_to_npy.py

# After conversion, .mat signal files can be deleted to reclaim ~135 GB
```

**Testing with fewer subjects:**

```bash
# Download only 10 subjects (~2.7 GB) for testing
.venv/bin/python3 src/datasets/sleep_psg_haystack/scripts/download_sleep_psg.py --n-subjects 10
```

### Step 1: Build timelines, window indexes, and benchmark samples

The generator handles everything: builds timelines (if not present), creates the participant split, builds the per-context-length window index, and generates QA samples for every applicable task × context length × split combination.

```bash
# Sleep stages dataset — all applicable tasks at default context lengths (15min, 1h, 2h, full)
.venv/bin/python3 -m src.datasets.sleep_psg_haystack.generation.generator \
    --label-class sleep_stages

# Arousals dataset — default context lengths (100s, 15min, 1h, full)
.venv/bin/python3 -m src.datasets.sleep_psg_haystack.generation.generator \
    --label-class arousals

# Custom context lengths (use 'full' for whole-recording)
.venv/bin/python3 -m src.datasets.sleep_psg_haystack.generation.generator \
    --label-class sleep_stages \
    --context-lengths-seconds 900 3600 full

# Generate specific tasks/splits only
.venv/bin/python3 -m src.datasets.sleep_psg_haystack.generation.generator \
    --label-class sleep_stages \
    --tasks localization counting \
    --context-lengths-seconds 900 \
    --splits test

# Build only the window indexes (no QA generation)
.venv/bin/python3 -m src.datasets.sleep_psg_haystack.generation.generator \
    --label-class sleep_stages --build-only
```

The pipeline:
1. **Builds timelines** from WFDB annotations → `data/sleep_psg/ts_haystack/{sleep_stages,arousals}/timelines/*.parquet` (~7 MB each)
2. **Creates participant split** → `data/sleep_psg/ts_haystack/participant_split.json` (695 train / 149 val / 150 test)
3. **Builds window indexes** → `data/sleep_psg/ts_haystack/{label_class}/window_index/ctx_{seconds}s.json` (one per context length; `full` is computed in-memory)
4. **Generates QA samples** → `data/sleep_psg/ts_haystack/{label_class}/tasks/{ctx_dir}/{task}/{split}/data.parquet`

Window indexes step a sliding window across each subject and keep starts where the window contains at least one regime bout. Stride defaults: `min(ctx/4, 30min)` for sleep_stages and `min(ctx/4, 5min)` for arousals.

Output parquet files are lightweight metadata (~KB each) — no signal data embedded. Default split sizes: `train` (1000 samples), `val` (150), `test` (150). Generation runs at ~8000+ samples/sec.

### Step 2: Visual verification

Generate annotated 13-channel plots for human inspection. Each sample produces two plots:

- `sample_NN_window.png` — the entire window the sample was drawn from
- `sample_NN_zoomed.png` — a 5-minute zoom inside the window centered on the answer region

```bash
# Verify sleep stages at 15min context, all applicable tasks
.venv/bin/python3 src/datasets/sleep_psg_haystack/scripts/verify_sleep_psg_haystack.py \
    --label-class sleep_stages \
    --context-length-seconds 900 \
    --n-samples 3

# Verify arousals at 100s context
.venv/bin/python3 src/datasets/sleep_psg_haystack/scripts/verify_sleep_psg_haystack.py \
    --label-class arousals \
    --context-length-seconds 100 \
    --n-samples 3

# Verify full-night sleep stages
.venv/bin/python3 src/datasets/sleep_psg_haystack/scripts/verify_sleep_psg_haystack.py \
    --label-class sleep_stages \
    --context-length-seconds full
```

Output: `data/sleep_psg/ts_haystack/{label_class}/verification/{ctx_dir}/{task}/sample_*.png`

Target bout(s) are highlighted as colored shaded regions and the Q&A is displayed at the bottom of each plot.

## Data Source

PhysioNet 2018 Challenge "You Snooze You Win" — 994 training subjects with:
- 13-channel PSG at 200Hz, ~7h per recording (~268 GB total as .npy)
- AASM sleep stage annotations in 30-second epochs (WFDB .arousal files)
- Arousal event annotations with sample-level timestamps
- Demographics: ages 18-93, 65% male

Citation: Ghassemi MM et al., "You Snooze, You Win: the PhysioNet/Computing in Cardiology Challenge 2018," CinC 2018. DOI: 10.22489/CinC.2018.049
